- 기존 실제 테스트에서 학생 수업기록 제출 → 강사 문구 수정 → 자동 연결 초안 → AI 문장 생성 → 테스트 일지 게시 완료.
- 이번 재점검에서 새로고침 후 김시은 수업기록, 강사 수정 과제, 게시된 일지 유지 확인. 최초 비밀번호 변경 안내 없음.
- npm run check 및 node --test tests/*.test.mjs: 테스트 파일 13개 통과.
- 자동 테스트는 DB 권한 분리, 원장/강사 댓글 개별 확인, 보충수업 연결, 일괄 초안 보존, 공지 작성 보존, 점수 중복 방지 등을 포함. 실제 브라우저 전 기능 테스트와는 구분함.

## 이번 수정 및 운영 반영

- admin-create-user, admin-delete-user, academy-ai: Auth.getUser에 실제 bearer token 전달.
- admin-create-user: 기본값/직접 전달된 4자리 비밀번호도 기존 프런트와 같은 호환 변환 적용. 기존 6자리 이상 값과 이미 변환된 값 유지.
- academy-ai: 모델 환경값이 없을 때 일지 AI와 같은 기본 모델 사용.
- 세 함수 Supabase 대시보드 배포 완료. legacy-secret 전용 게이트 대신 함수 내부의 실제 Auth 검증 및 활성 역할 검증 유지.
- 실제 운영 endpoint에 invalid-audit-token으로 요청: 세 함수 모두 401. 등록/삭제 작업은 실행하지 않음.

## 아직 완료가 아닌 항목

1. 실제 학부모 로그인 → 해당 자녀만 열람 → AI 일지 확인 → 댓글 작성 → 강사/원장 확인의 브라우저 전체 검증. 현재 가족 연결을 위한 확인용 학부모 계정 승인 대기. 기존 학생을 새로 만들 필요 없음.
2. 기존 학생 전체 비밀번호 1234 통일: 실행되지 않음. 앞선 실제 로그인에서 김시은은 123456으로 성공. 신규 계정 호환 수정이 기존 비밀번호까지 변경하지는 않음.
3. 일지의 과제 문구는 수업 안내에 보이지만 사진 제출용 homework 항목은 자동 생성되지 않음. 현재 별도 과제 출제가 필요.
4. 질문 AI의 실제 사진 첨부 → 답변 초안 생성은 이번 점검에서 미실행. 인증 수정 배포와 잘못된 토큰 차단만 운영 검증.
5. 신규 계정 생성/영구 삭제는 운영 학생 데이터 보호를 위해 실제 실행하지 않음. 로컬 모의 테스트로 인증 및 신규 비밀번호 변환 확인.
6. 부모용 문장에서 교재·페이지·단원 자동 볼드 표현은 현재 threadPanel의 일반 텍스트 렌더링에 구현되지 않음.
7. 모바일 실기기, 대량 동시 접속, 사진 업로드/다운로드 및 백업 복구는 이번 점검 범위에서 미검증.
